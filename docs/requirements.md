# FrigoTab requirements and acceptance behaviors

This document is the behavior inventory for acceptance-test-driven development. The work is isolated on `codex/gpt-atdd-stabilization`; it must not be treated as a change directly on `master`.

## Test policy

The repository contains 98 green plain C# MSTest methods in 12 timestamped test families. There is no Reqnroll/Gherkin layer, no `.feature` file, and no intentionally-red test lane or task. Each `[TestClass]` and matching file starts with `TYYYYMMDDTHHMMSSZ_NNN_DescriptiveFamilyName`; the family suffix is stable and the current set ends at `_077`. Test methods use descriptive plain C# names. A naming-convention acceptance test enforces the class/file family policy, and existing family timestamps are not changed during refactoring.

The tests are split by evidence, not by pass/fail status:

- **Behavioral acceptance tests** use `SwitcherApplication` with an in-memory session port. They protect externally visible interaction without creating HWNDs or installing hooks.
- **Production contract tests** inspect executable composition, source-level Win32 declarations, native resource seams, and DWM fakes. They protect architecture and failure handling but cannot prove every native call on every desktop.
- **Manual Windows checks** use real hooks, HWNDs, DWM, focus, monitor/DPI changes, lock/unlock, protected surfaces, UIPI/elevation, and pointer input. They are release evidence, not a substitute for deterministic tests.

## Current behaviors

| Startup | Start a form-less WinForms message loop, acquire the per-user single-instance mutex, show a tray icon, avoid a taskbar button, and keep the switcher hidden until a gesture. | Composition/source contract tests and mutex test. | Start a Release build on a real desktop and launch a second copy. |

## Defects addressed by the current green suite

The current branch protects the selected stabilization fixes and adjacent regressions: fail-open admission, balanced key suppression, timing-independent sticky Alt release, event-derived and dual-side modifiers, native-Alt recovery, dedicated hook message-loop ownership, synchronous suppression with deferred UI work, admission tokens, bounded critical delivery, stale-callback invalidation, complete forward/reverse failed-open replay with direction preserved across Shift changes, pointer-sized `INPUT` layout, startup without a stack-trace visibility hack, no display-mode reset or fabricated activation message, transactional construction/cleanup, stale-window skipping, restored-rectangle monitor selection, staged DWM thumbnail visibility and unregister diagnostics, shell desktop wallpaper/icon capture without application reconstruction, synchronous first-frame painting and black fallback, Unicode and pointer-sized declarations, deterministic native/GDI disposal, single-instance admission, visual-tile pointer routing, the historical foreground input nudge without thread-input attachment, and intentional activation handoff without interruption-state reset.

These are green executable specifications, not a promise that a protected or unusual Windows surface behaves identically to an ordinary desktop. The manual matrix is intentionally retained for those cases.

## Explicit design caveats

- The primary backdrop is the latest static shell image prepared while idle; applications can continue changing behind the overlay without changing the displayed wallpaper/icon background for that session.
- FrigoTab is deliberately sticky: releasing Alt does not activate the initially selected application. Choose with D1..D9, NumPad1..NumPad9, or a pointer click; cancel with Escape or Alt+F4.
- Protected, secure, unavailable, or capture-disabled surfaces may render as black; opening remains fail-open.
- A display/DPI topology change currently closes the session safely rather than rebuilding the snapshot and every native tile in place.
- DWM failure falls back to the icon/title overlay; that fallback is intentionally less informative than a captured thumbnail.
- `SetForegroundWindow` can still be denied by Windows focus/UIPI policy. FrigoTab uses its historical dummy input nudge rather than `AttachThreadInput`; the overlay remains admitted and usable, and native Alt+Tab is not replayed merely because focus acquisition was denied.
- Pointer routing through separate layered/transparent tile forms has a history of fragility and must be verified on supported Windows configurations; it is not currently documented as a reproducibly confirmed click-through bug.
- Future work can extract narrower keyboard, window-catalog, display-topology, activator, view, and clock ports when a new acceptance behavior requires stronger isolation.
